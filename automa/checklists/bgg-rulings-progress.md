# Rulings knowledge base vs the code

Progress of checking each file in [../bgg-rulings/](../bgg-rulings/) against what the code does, and against the
three Automa rulebooks (A and B from 2023-08-15, C from 2023-11-14). A ruling is keyed by the BGG article id in its
link (with `-1`, `-2` when one post answers several questions), so rows survive a re-sort of the knowledge base.

Code status:

- `applied`: recorded in [designer-rulings.md](designer-rulings.md) "Applied in the code", and the code agrees.
- `matches`: the code already does this. The rulebooks say the same, or it is not worth a row.
- `mismatch`: the code, or one of our own readings in designer-rulings.md, does something else. Needs a decision.
- `n/a`: nothing for the code to do (physical components, printed wording, something the app does not offer).
- `open`: not settled from the code yet.

Rulebook:

- `agrees`: a rulebook says the same.
- `extends`: the rulebook covers the topic but not the point the ruling settles.
- `differs`: the rulebook says something else. The designers' forum answers win (Nick, 2026-10-13), so these are
  listed with what the code follows.
- `silent`: no rulebook covers it (usually only a printed card does).
- `n/a`: no rulebook counterpart.

`hedged` and `inferred` carry over from the knowledge base: a mismatch against "I think" is a weaker case for
a change than one against a flat answer. A `superseded` ruling, or a `prototype` one that the published rules
replaced, is `n/a` when it disagrees with the code: the later source is what counts.

### Where the forum and the rulebooks differ (15)

- **B07 Local Neural Instance** ([44711805-2](https://boardgamegeek.com/thread/3350125/article/44711805#44711805), Nick), A p.7 "(See Game End on page 10 for the effect this tile has on MarsBot’s scoring.) Then, destroy this card.": A p.7 puts 'Then, destroy this card' after the cannot-place fallback, so read literally the card is destroyed even when the tile is not placed, while the printed card lists the destroy first; the ruling says destroy only on success and the code follows it.
- **B07 Local Neural Instance** ([44714350](https://boardgamegeek.com/thread/3350125/article/44714350#44714350), Dávid), A p.7 "(See Game End on page 10 for the effect this tile has on MarsBot’s scoring.) Then, destroy this card.": Same wording issue as the previous ruling: A p.7 lists the destroy after the cannot-place fallback, but the ruling has an unplaced tile discard the card instead; the code follows the ruling.
- **Direct interaction with MarsBot** ([44758514](https://boardgamegeek.com/thread/3355768/article/44758514#44758514), Dávid), A p.4 "move MarsBot’s corresponding tracker backwards one space": The rulebook says to move the tracker back one space per decrease effect, most likely assuming 1-step cards, while the ruling moves it back by the full number of steps; the code follows the ruling.
- **Drafting** ([45118494-2](https://boardgamegeek.com/thread/3398289/article/45118494#45118494), Nick), B p.2 "These 4 (in rare cases it can be 5) cards become MarsBot's action deck.": B p.2 checks all 4 drafted cards and discards nothing (giving a 5-card deck) when every card matches the priority, while the ruling always discards the one with the fewest matches; the code follows the ruling.
- **Drafting** ([48285590-2](https://boardgamegeek.com/thread/3781613/article/48285590#48285590), Nick), B p.2 "Repeat this until a card is discarded or all 4 have been checked.": B p.2 discards nothing when all 4 cards match the priority (hence a possible 5-card deck), while the ruling says MarsBot always discards one; the code follows the ruling except for Credicor and Spire, whose all-tied case B p.3 prints as discard nothing.
- **Expedited Construction** ([44720677](https://boardgamegeek.com/thread/3350125/article/44720677#44720677), Dávid), C p.4 "(if tied: adjacent to most tiles of these types, then see Tile Placement Tiebreakers)": The rulebook ranks spaces by the most greenery and ocean neighbours of any mix before the placement tiebreakers, so 3 oceans would beat 2 greeneries; the card author's ruling goes straight to the usual city rules, and the code follows the ruling.
- **Final greenery** ([48285468-2](https://boardgamegeek.com/thread/3781613/article/48285468#48285468), Nick), A p.10 "Move the tracker forward and perform MarsBot’s greenery action for each track this applies to.": The rulebook moves the tracker forward for each final greenery, while Nick only counts the tracks with a greenery ahead and leaves the cube; the code follows the rulebook and moves it, and the no-corp-effects option is the difficulty modifier he describes.
- **Floaters** ([44631596](https://boardgamegeek.com/thread/3341542/article/44631596#44631596), Nick), C p.4 "If playing without Venus Next, place a resource token in the Titan storage area of the Colonies shipping board.": As written the ruling says to ignore the floater icon without Venus Next, but C p.4 puts the floater in the Titan area under Colonies even without Venus Next; later posts narrowed the ruling and the code follows that narrowed reading.
- **Floaters** ([45267693](https://boardgamegeek.com/thread/3415280/article/45267693#45267693), Nick), C p.4 "If playing without Venus Next, place a resource token in the Titan storage area of the Colonies shipping board.": The post says floaters only matter with Venus Next, but C p.4 has the floater icon feed the Titan area under Colonies without Venus Next; the code follows the later widened rulings, which match C p.4.
- **Greenery placement** ([44711805-6](https://boardgamegeek.com/thread/3350125/article/44711805#44711805), Nick), A p.9 "equally high number of adjacent MarsBot cities and an equally low number of your cities": A p.9 treats spaces as tied only when both the own-city count and the player-city count are equal, while the designer says the aim is the greatest net gain; the code follows the net-gain ruling.
- **Magnate** ([46731527](https://boardgamegeek.com/thread/3534424/article/46731527#46731527), Dávid), C p.15 "Magnate - As usual (blue and green cards in played pile)": C p.15 says MarsBot's Magnate counts blue and green cards while C p.9 and the helper action on C p.12 say green only; the ruling calls the blue-and-green wording a mistake and the code counts green only.
- **Milestones and awards** ([40477875](https://boardgamegeek.com/thread/2883930/article/40477875#40477875), Nick), A p.8 "or it is not ahead of you on any requirement, it takes a Failed Action instead": A p.8 (and A p.6) makes the award action fail unless MarsBot is ahead of you, so a tie fails, while this 2022 quote lets a tie fund; the code follows the published rulebook.
- **Setup** ([46979373](https://boardgamegeek.com/thread/3622481/article/46979373#46979373), Nick), B p.1 "After selecting and playing your own corporation (but before selecting and playing your Prelude cards": B p.1 literally puts selecting and playing your corporation before selecting your Prelude cards, while the designer says only the corporation reveal and setup must come first; the code follows the ruling.
- **Setup** ([46982860](https://boardgamegeek.com/thread/3622481/article/46982860#46982860), Nick), B p.1 "After selecting and playing your own corporation (but before selecting and playing your Prelude cards": B p.1 literally puts selecting and playing your corporation before selecting your Prelude cards, while the designer confirms that choosing everything at once is fine if the corporation is revealed first; the code follows the ruling.
- **Tile placement** ([44709876](https://boardgamegeek.com/thread/3342916/article/44709876#44709876), Dávid), C p.10 "count through each of the remaining tied spaces, up to the card’s cost. Place the tile on the final hex.": The rulebook counts up to the card's cost, which reads as one-based, while Dávid's zero-based count shifts each result by one; the code follows the rulebook and Nick.
